# 運営サイクルガイド

イベント作成から振り返りまでの手順を説明します。期限が近いタスクは Slack で確認し、
完了したタスクは Dashboard でチェックします。

## 準備フェーズ

| 時期 | やること | 使用する機能 |
| --- | --- | --- |
| −5 週 | イベント作成、会場・役割を記入して PR をマージ | `ichiza new` が定義、Dashboard、募集文を生成 |
| −5〜−4 週 | 会場確保、募集ページ公開、登壇依頼 | Dashboard の期限つきチェックリスト |
| −4〜−3 週 | 登壇者を `event.yaml` に追記し、募集文を更新 | `ichiza registry` |
| −3 週 | SNS・コミュニティで告知 | remind の X intent URL |
| −2 週 | 配信枠作成（hybrid / online） | mode に応じた lifecycle タスク |
| −1 週 | 参加者数を最終確認 | `ichiza watch` |
| −3 日 | 配信リハーサル、直前連絡 | `ichiza remind` |
| 当日 | 勉強会を実施 | — |
| +1〜+10 日 | お礼、アンケート、振り返り | Dashboard の followup タスク |

### Dashboard の使い方

1 イベントの運営タスクは 1 件の Dashboard Issue にまとまります。

- タスク完了は最上位の `- [ ]` を `- [x]` にする
- タスク本文や Notes に追加した入れ子チェックボックスは完了判定に影響しない
- 全タスクが完了すると Issue が閉じる
- チェックを戻すと Issue も再度開く
- タスクを実施しない場合も、削除ではなく「実施しないと判断した」完了としてチェックし、
  必要なら理由を Notes に残す
- タスクのタイトル、期限、担当者を変える場合は `tasks.yaml` を PR で更新する。
  main へマージすると、task ID ごとの完了状態と Notes を残したまま Dashboard が更新される

毎朝の Slack digest は、Dashboard の未完了状態を読み、期限超過と 7 日以内のタスクを通知します。
`ichiza.yaml` に Slack User ID がある担当者にはメンションします。

GitHub Projects では Dashboard Issue をイベント単位のカードにします。
タスクごとのカードを増やさないため、Project の列は企画中・準備中・開催済みなど
イベント全体の状態に使えます。

## 実施（当日）

あらかじめ決めた役割分担と手順に沿って進めます。

| タイミング | やること |
| --- | --- |
| 開始 90〜60 分前 | 机・椅子・案内、Wi-Fi、電源、受付導線を確認 |
| 開始 60〜30 分前 | 配信ツール、音声経路、配信枠を確認 |
| 開始 30 分前〜 | 受付開始、参加者リスト照合 |
| 本編 | 進行とタイムキープ |
| 終了後 | 撤収、忘れ物、配信停止、アーカイブを確認 |

当日に見つけた問題は Dashboard の Notes に残します。継続して対応する必要がある障害や改善は、
別の Issue として登録します。

## 振り返り（開催後 +1〜+10 日）

| 期限 | タスク | 内容 |
| --- | --- | --- |
| +1 日 | お礼 | 登壇者、会場、参加者へのお礼 |
| +3 日 | アンケート収集 | 回答回収、開催記事やアーカイブの案内 |
| +10 日 | 振り返り | Notes とアンケートを材料に Keep / Problem / Try を整理 |

振り返りで見つかった改善点は、次のいずれかに反映します。

- **運営の改善** → `templates/lifecycle.yaml` にタスク、期限、担当ロールの改善を反映
- **ツールの改善** → [gr1m0h/ichiza](https://github.com/gr1m0h/ichiza/issues) に Issue を作る

`templates/lifecycle.yaml` を更新すると、次回のイベント作成時から変更内容が反映されます。
すべてのチェックボックスが完了し、Dashboard Issue が閉じたら運営タスクは終了です。

## Web コックピットを使う場合

Web は Dashboard Issue の内容を表示・更新するための画面です。データは GitHub に保存されます。

- イベント一覧で開催日と進捗を確認
- イベント詳細でタスクをチェック
- My Page で自分の担当タスクと期限状態を確認
- 期限を確認して作業の優先順位を決める

Web は送信前に GitHub の `updated_at` を確認し、画面を表示したあとに変更されていた場合は 409 を返します。
ただし、GitHub API では更新時の条件を指定できないため、確認してから更新するまでの間に
行われた同時編集は検出できません。
競合が表示された場合や複数人で同時操作する場合は、ページを再読み込みして最新状態を確認してください。

## 運用中に設定を見直す

| 気づき | 反映先 |
| --- | --- |
| タスクの不足、期限のズレ、担当ロールの不一致 | 運営リポジトリの `templates/lifecycle.yaml` |
| 特定イベントだけの事情 | 対象イベントの `event.yaml` / `tasks.yaml` / Dashboard Notes |
| 定型作業が手作業のまま残る | ichiza 本体の機能提案 |
| ichiza の不具合 | ichiza 本体のバグ報告 |

本体の `v0` タグが更新されると、workflow の参照先を変えなくても更新内容が反映されます。
